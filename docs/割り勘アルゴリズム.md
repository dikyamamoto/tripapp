# 割り勘アルゴリズム

本ドキュメントでは、旅行計画・割り勘スマホアプリ「TripApp (仮称)」における、送金回数を最小化するための自動清算（割り勘）アルゴリズムについて定義します。

---

## 1. 基本概念と定義

### 1.1. 記法と定義
* **メンバーの集合**: $M = \{m_1, m_2, \dots, m_n\}$
* **支払額 ($P_i$)**: メンバー $m_i$ が旅行中に実際に支払った（立て替えた）合計金額。
* **負担額 ($U_i$)**: メンバー $m_i$ が消費した（支払うべき）合計金額。
  * **個別出費の負担**: 
    出費 $E$ に対し、支払額を $A_E$、その出費の対象メンバー集合を $T_E \subseteq M$ とする。
    各対象メンバー $m_j \in T_E$ の負担分は $A_E \div |T_E|$ となる。
    メンバー $m_i$ の総負担額 $U_i$ は、自身が対象となっているすべての出費の負担額の合計である。
* **純貸借 ($B_i$)**: メンバー $m_i$ の貸し借りの最終バランス。
  $$B_i = P_i - U_i$$
  * $B_i > 0$ : **もらい手 (Creditor)**。支払った額が負担額より多いため、お金を受け取る権利がある。
  * $B_i < 0$ : **払い手 (Debtor)**。支払った額が負担額より少ないため、お金を支払う義務がある。
  * $B_i = 0$ : **清算不要**。

---

## 2. 送金回数最小化のアルゴリズム (Greedy法)

全員の純貸借 $B_i$ の合計は必ず 0 になります（$\sum_{i=1}^n B_i = 0$）。
この性質を利用し、最も少ない送金ステップで全員の貸し借りを 0 に近づけるために、以下の欲張り法（Greedy Algorithm）を採用します。

### 2.1. アルゴリズム手順

1. **初期バランスの計算**:
   各メンバー $m_i$ の純貸借 $B_i$ を計算する。

2. **グループ分け**:
   * $B_i < 0$ のメンバーを **Debtors (払い手)** リストとする。
   * $B_i > 0$ のメンバーを **Creditors (もらい手)** リストとする。
   * $B_i = 0$ のメンバーは処理から除外する。

3. **ソート**:
   * Debtors リストを、不足額の絶対値 $|B_i|$ が大きい順（降順）にソートする。
   * Creditors リストを、受取額 $B_i$ が大きい順（降順）にソートする。

4. **マッチングと精算ルートの決定**:
   Debtors の先頭（最も多く支払うべき人 $D$）と、Creditors の先頭（最も多く受け取るべき人 $C$）を取り出す。
   * **送金額の決定**: 
     $$A = \min(|B_D|, B_C)$$
   * **清算の記録**: 
     「$D$ は $C$ に $A$ 円送金する」という清算ルートを追加する。
   * **バランスの更新**:
     $$B_D \leftarrow B_D + A$$
     $$B_C \leftarrow B_C - A$$

5. **リストへの再配置**:
   * 更新後の $B_D$ が依然として 0 未満であれば、Debtors リストの適切な位置（ソート順を維持）に戻す。
   * 更新後の $B_C$ が依然として 0 より大きければ、Creditors リストの適切な位置（ソート順を維持）に戻す。

6. **終了条件**:
   Debtors および Creditors リストが空になる（全員の $B_i \approx 0$ になる）まで、ステップ4〜5を繰り返す。

---

## 3. 計算例

3人のメンバー A, B, C で旅行に行き、以下の出費があったとします。
* Aがレンタカー代として 9,000 円支払った（対象: A, B, C）
* Bが食事代として 3,000 円支払った（対象: B, C）

### 3.1. 各メンバーの負担額と支払額の集計

1. **レンタカー代 9,000円 (対象: A, B, C)**
   * Aの負担: 3,000円
   * Bの負担: 3,000円
   * Cの負担: 3,000円
2. **食事代 3,000円 (対象: B, C)**
   * Bの負担: 1,500円
   * Cの負担: 1,500円

**集計結果**:
* **支払額 ($P$)**:
  * $P_A = 9,000$ 円
  * $P_B = 3,000$ 円
  * $P_C = 0$ 円
* **負担額 ($U$)**:
  * $U_A = 3,000$ 円
  * $U_B = 3,000 + 1,500 = 4,500$ 円
  * $U_C = 3,000 + 1,500 = 4,500$ 円
* **純貸借 ($B = P - U$)**:
  * $B_A = 9,000 - 3,000 = +6,000$ 円 (Creditor)
  * $B_B = 3,000 - 4,500 = -1,500$ 円 (Debtor)
  * $B_C = 0 - 4,500 = -4,500$ 円 (Debtor)

### 3.2. アルゴリズムの適用

* **初期状態**:
  * Debtors: $[C(-4500), B(-1500)]$
  * Creditors: $[A(+6000)]$

1. **ステップ1**:
   * Debtorsの先頭 $C(-4500)$ と Creditorsの先頭 $A(+6000)$ を取り出す。
   * 送金額 $A = \min(|-4500|, 6000) = 4500$ 円。
   * **清算ルート**: `C -> A に 4,500円送金`
   * バランス更新:
     * $B_C = -4500 + 4500 = 0$
     * $B_A = 6000 - 4500 = +1500$
   * リスト更新:
     * $C$ は 0 になったため除外。
     * $A$ は $+1500$ なので Creditors に戻す。
     * Debtors: $[B(-1500)]$
     * Creditors: $[A(+1500)]$

2. **ステップ2**:
   * Debtorsの先頭 $B(-1500)$ と Creditorsの先頭 $A(+1500)$ を取り出す。
   * 送金額 $A = \min(|-1500|, 1500) = 1500$ 円。
   * **清算ルート**: `B -> A に 1,500円送金`
   * バランス更新:
     * $B_B = -1500 + 1500 = 0$
     * $B_A = 1500 - 1500 = 0$
   * リスト更新:
     * 全員のバランスが 0 になったため終了。

### 3.3. 最終清算ルート
* **C が A に 4,500 円支払う**
* **B が A に 1,500 円支払う**

送金回数はわずか **2回** で精算が完了します。
